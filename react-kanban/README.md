## О проекте

Kanban-доска для управления задачами, реализованная на стеке **Webpack + React + TypeScript** с использованием **SCSS** для стилизации. Приложение соответствует строгим требованиям к сортировке, визуальному выделению просроченных задач, drag & drop между колонками, поиску по тексту и датам, персистентности состояния и адаптивной вёрстке в диапазоне от 768 до 1920 пикселей.

Проект построен без сторонних UI-библиотек и drag & drop-фреймворков: используется нативный HTML5 Drag and Drop API, изолированные SCSS-модули на компонент и локальные `woff2`-шрифты.

---

## Ключевые особенности

- **Четыре колонки** (`To Do`, `In Progress`, `Review`, `Done`); внутри каждой задачи отсортированы по `startDay` по возрастанию.
- **Просроченные задачи** обводятся красным (`endDay < today` и `type !== 'done'`); карточки в колонке `Done` не выделяются.
- **Удаление** доступно в любой колонке по hover на карточку; **редактирование** — только в `To Do`, что соответствует макету.
- **Drag & Drop** — перенос между колонками с автоматической пересортировкой по `startDay` после изменения статуса.
- **Поиск** — инкрементальный, по описанию (без учёта регистра) и по датам в формате `dd.mm.yyyy`.
- **Персистентность** — состояние сохраняется в `localStorage` после каждого изменения.
- **Адаптивность** — горизонтальный скролл при `< 768px`, ограничение и центрирование при `> 1920px`.
- **Современный CSS** — каскадные слои `@layer`, контейнерные запросы `@container` и функция `clamp()`.

## Техническая реализация

### Состояние и персистентность

Состояние задач хранится в корневом компоненте `App`. При монтировании выполняется чтение `localStorage` с валидацией записей; при отсутствии значения или невалидных данных загружается `tasks.json`. Запись выполняется после каждого изменения через `useEffect`. Ключ хранилища — `react-kanban.tasks`. Валидатор проверяет типы полей, допустимые статусы и корректность временных меток.

### Drag & Drop

Нативная реализация через события `dragstart`, `dragover`, `drop`, `dragend`. Перетаскивание разрешено только между колонками: смена статуса выполняется в чистой функции `moveTask()`, которая возвращает новый массив без мутаций. Пересортировка внутри целевой колонки выполняется автоматически при рендере по `startDay`, поэтому карточка встаёт на позицию, соответствующую её дате начала, а не в конец списка.

### Поиск

Единая строка поиска обрабатывается нормализатором: запрос приводится к нижнему регистру, проверяется соответствие подстроке в поле `text`, а также в отформатированных датах `startDay` и `endDay`. Поиск по дате инкрементальный: частичный ввод `19` возвращает все карточки, где хотя бы одна из дат содержит `19`, а полный ввод `19.12.2024` сужает выборку до точного совпадения.

### Адаптивность

Раскладка доски — CSS Grid с `grid-template-columns: repeat(4, minmax(0, 1fr))` и минимальной шириной 768px. Ниже этого порога появляется горизонтальный скролл на обёртке. Выше 1920px контейнер ограничен по `max-width` и центрирован. Отступы и зазоры заданы через `clamp()`, сглаживая переход между 768 и 1024px. Карточки используют `container-type: inline-size`: при узкой колонке лейблы переносятся над значениями, уменьшается шрифт дат, а описание обрезается.

### Оптимизация рендеринга

Карточки обёрнуты в `React.memo`, обработчики — в `useCallback`, отфильтрованные и отсортированные списки — в `useMemo`. Обновление задач выполняется иммутабельно, чтобы `memo` реально предотвращал перерисовку соседних карточек при изменении одной.

## Установка и запуск

### Требования

- **Node.js** версии 18.18.0 или выше
- **npm** (поставляется вместе с Node.js)

### Установка зависимостей

```bash
npm install
```

### Запуск в режиме разработки

```bash
npm run start
```
Приложение будет доступно по адресу `http://localhost:3000/`.

### Сборка для production

```bash
npm run build
```
Готовый бандл будет находиться в директории `dist/`.

### Основные скрипты

| Команда             | Описание                                    |
|---------------------|---------------------------------------------|
| `npm run start`     | Запуск dev-сервера (Webpack)                |
| `npm run build`     | Сборка production-версии в `dist/`          |
| `npm run test`      | Запуск unit- и компонентных тестов (Vitest) |
| `npm run typecheck` | Проверка типов TypeScript (`tsc --noEmit`)  |

## Тестирование

Фреймворк — **Vitest** с JSDOM и React Testing Library. Тесты вынесены в директорию `tests/` с зеркальной структурой `src/`:
- `tests/utils/` — unit-тесты для `overdue`, `taskFilters`, `taskSort`, `taskValidation`, `localStorageTasks`, `moveTask`, `dateFormat`.
- `tests/components/` — компонентные тесты для `KanbanBoard` и `TaskCard`.

**Тест функции просроченности:** `tests/utils/overdue.test.ts`.
